# Relevo v6: whose turn is it?

Every row in Reviews, Runs and Agents answers one question first: whose turn is it. This page holds the
grammar the views share and the decisions behind it. The components live in `mods/relevo/ui.js`.

## The row

`lane · body · edge`, left to right:

- **lane**, a 24 px column with one glyph: a filled disc for *needs me*, the spinner for *in flight*, a check for
  *ready*, a ring for *open*, a small dot for *old*, a warning sign for *stuck*.
- **body**: the kind glyph, what it is in semibold, and the one reason it is here in plain words.
- **edge**: its age and the one action.

Rows are separated by a hairline that starts past the lane. A row waiting on you is tinted (`blocked` at 7%).
Selection is a full accent outline over `selected`. The selected row opens in place with its extra lines; the
detail (review pane, a result, compare, accept several) opens only on purpose.

## Views

Runs has three levels (`inbox-runs.js`, words in `lib/run-panel.js`): runs grouped Needs me, In flight, Ready and Not
started; a run's tasks grouped Needs me, Stuck and In flight; and a task. One list of rows feeds the drawing and the keys.

Reviews has two views. **Now** groups every item by whose turn it is (Needs me, In flight, Ready, then the
ones waiting on others, folded); the order within a group follows the source (agents, Desktop, landing, run
results, review requests, your PRs, local work, linked work). **Maintenance** holds what can wait, grouped by what cleaning up would
cost: Safe to remove, Needs a look and Old, with the same legend as Now. One list of
entries (`inbox-now.js`) feeds both the drawing and the keyboard, so the order you see is the order the keys walk.
`reveal(id)` selects a row wherever it lives, switching view and opening its fold.

## Glyphs and charts

28 SVG files in `mods/relevo/icons/`, on a 12 px grid with a 1.5 stroke and square caps, tinted with
`text_color` like `spinner.svg`. Small charts: `seg` (one box per check), `diffRatio` (five squares),
`ageTicks` (1m, 5m, 15m, 1h, 1d), `legs` (who did what), `band` (usage with a pace tick), `tag`, `checkbox`.

## Colour, type and motion

- Theme tokens only. A tint is a token with an alpha suffix (`t.blocked + "12"`); a test fails on a hex colour
  in a view. Two palettes are data, not styling: account colours in `config.js`, and the folder marks the agents
  list shares with the space-folders mod (`relevo-agents/folder-colors.js`).
- Herdr supplies the faces (`ui_font_family`, `font_family`); the mods bundle no font and keep to 11 and 13 px.
- No new motion: the spinner is the only thing that moves, as before.

## Decisions

- **Rows and views shipped together.** The row grammar and the regrouping touch the same list; shipping them apart
  would have left a release with rows under source-named sections.
- **The badge is the Needs me count**, computed from the same entries as the legend, so the two never disagree.

- **A waiting agent stays open.** Its question, the command or plan it asks about and its numbered answers are
  always in sight, because answering a permission without seeing it is unsafe. Its other actions wait for the
  selection like any row.
- **Selection does not need the keyboard.** A clicked row stays open until Esc, another selection or a second
  click on it; before, the highlight only showed while the list had focus. A click never hides the rows above.

- **A run opens in the panel.** Runs is three levels in one place: the runs, one run's tasks, one task with who did what
  and the decision. Enter or a click goes in, Esc comes back, and the open run is the shared scope (`relevo.goals.scope`).
  The run window stays for planning a run (prompt, repository, agents, plan) and for the deep views a task links to:
  **See the diff** and **More**. Accepting from the panel sends the same command with the revision on screen, and a click
  arms it like the A key does, so one stray click never accepts.
- **A run row answers three questions.** What it is, what it does or wants now, and what it shipped, on two labelled
  lines. Shipped only claims what Relevo saw: open and draft linked PRs, PRs it watched merge, and the draft PRs it opened.
- **A step shows when it started, not how long it took.** The design drew durations ("14m", "48s"); attempts only record
  their start, so each row of who did what shows its age.

- **Needs me is a disc, not a capsule.** The design drew a 6 px vertical capsule in the lane. At the leading edge
  of a row it reads as an accent strip, which Relevo does not use, so the lane uses an 8 px disc.
- **Folder marks keep the sidebar's colours.** space-folders paints folders from its own palette, so the agents
  list reads the same values from one file instead of following the theme.

- **Safe means merged, and Remove loses nothing.** A worktree is under Safe to remove only when its branch merged
  and it is clean, unlocked, unused for a day and has no ignored files to keep. One that never merged is under Needs
  a look even with nothing to lose, with its own Remove on the row: a batch only ever takes merged worktrees, and
  never deletes a file nobody saw.
- **One question for several, the same checks for each.** The sheet says only what holds for the selection; each
  row then passes the look-again of its own Remove. `X` and Remove N leave out rows with a space, which `x` can
  still add: the sheet then says how many spaces close.
- **The sheet does not promise branches stay on GitHub.** A merged PR's branch is often deleted there, so it says
  the work is merged, which is what was read.
- **"pushed, not merged", not "pushed, no PR".** Only merged PRs are read, so an open PR can't be ruled out.
- **Save a copy is what git can save.** A patch or a bundle where there is uncommitted or unpushed work; files git
  ignores have no saved copy, so that row offers Open folder and names them before Delete forever.
- **`d` asks, Enter answers.** On a row or on a selection, a repeated `d` never removes anything.
- **Enter never deletes.** On a worktree it opens its space, on a stale branch it does nothing; Delete branch is a
  click, and `git branch -d` is the guard.
- **Recent and unread worktrees stay folded.** They are not safe and there is nothing to look at yet.
- **The Maintenance tab is the legend's sum.** Safe to remove, Needs a look and Old; recent or unread worktrees are
  in neither. Stale branches are read when their fold opens, so Old and the tab count them from then on.
