# Reviews and Runs

**Reviews** preserves the existing review queue and its PR, CI, conflict, reply, draft, addressed-work and Land controls. **Runs** is the place to start and follow agent assignments. It shows run summaries and progress, without duplicating PR, diff or session cards. Both are direct top-level destinations. Reviews opens directly on actionable work; the five summary tiles are removed. Stored goal records, mode preferences and command names retain their existing format.

Run cards show the title, one current action and a concise progress explanation: assigned executor/reviewer, pending report, blocker, pause or prerequisite, plus the next transition. Sending and uncertain delivery are distinguished from awaiting a report. Enter opens that action. Full outcomes, criteria, ownership, recommendations and notes live behind **Edit** or the run window, rather than repeating in the queue. Saved prose cannot override live task state. **View in Reviews** selects the corresponding result or linked change in the review queue. **Ready for you** lists each workflow result awaiting human acceptance and unresolved saved decisions. Opening a result selects its exact task; accepting it removes the review entry while preserving run history. Workflow polling and the attention count work in both views. Draft and addressed source actions remain in Reviews, with run linking and context actions. An unreadable workflow shows an error instead of stale actionable results.

**+ Run** opens a prompt-first composer. The first prompt line supplies the name unless an optional title is entered. **Choose agents** saves the brief, then opens setup with the same prompt and the focused repository suggested. It does not dispatch work. A new run without tasks has no empty task sidebar; other repositories are available through **Change repository**. Implementation and independent review require different connected sessions. Creating a task saves a plan; **Start** is the explicit execution boundary. Existing multi-outcome plans remain available.

The file/repository bar appears with Files and Changes, not above Reviews or Runs. **Find file…** opens the existing keyboard-accessible file picker. Refresh keeps PR freshness and failure information in its tooltip; errors remain visible in the queue. The repeated Inbox header and inner mode tabs are removed.

The queue's focus control enables arrow-key navigation. Home/End reach the first/last item, G selects the next run, F focuses it or returns to all work, and E opens context. R on a run selects its review entry; R on a source opens its available diff. S on a PR opens skill/account choices. **?** exposes searchable shortcuts. In a result window, A prepares acceptance and Enter confirms the same task/revision; Escape cancels preparation. R opens a change request and Command/Ctrl+Enter submits nonempty feedback (or prepares a follow-up at the round limit). Acceptance advances to the next pending result. Tab and Shift-Tab move between controls. Typing in a descendant input does not trigger queue actions.

Existing run editing retains Brief, Outcomes and Ownership. A pending question can explicitly link to a task through **Link to result…**. It then appears with that result instead of as a second queue entry. Only an explicit acceptance for the task’s current revision resolves the linked question. Changed question text, missing tasks, cancellation, unreadable status or unverifiable acceptance keep the question separate. No legacy question is linked by guessing. Saving a resolved question preserves its history and rechecks the acceptance.

Notes record local feedback; they do not send messages, approve PRs or validate outcomes automatically. Closing a goal still requires validated outcomes and no unresolved decision. Accepting a workflow result records its reviewed revision and releases only eligible already-started dependencies. It does not merge a PR or close the goal.

Review comments retain **Save comment**, **Cancel** and **Delete comment**. Enter saves; Escape cancels while retaining the prior saved comment. Empty text does not delete implicitly. Selected/all-file viewed controls and the separate checkpoint remain available.

Accounts move to the status bar: icon, short name and a five-hour usage ring. Clicking opens weekly usage, reset information, context controls and account actions. Missing and stale readings are explicit. Existing monitoring and keyboard commands retain one owner. See [design rationale, references and follow-up ideas](runs-ux.md).

Product labels are English; user-authored content retains its language. Private projects, sessions, screenshots and exercise results stay outside the repository. Public sources are in the [research record](workflow-research.md); see the [continuation guide](workflow-continuation.md) for deployment and review boundaries.
